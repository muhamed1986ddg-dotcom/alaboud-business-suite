# v25.14.60 — JAD Revision Isolation

هذا الإصدار يعالج رفض حفظ تحديث جاد برسالة `Application state changed before this write could commit`.

السبب كان أن سجلات التكامل ونشاط API كانت تستخدم مسار write-behind على `app_state` أثناء عمل موصل جاد الطويل، فتستطيع رفع revision بالتزامن مع الحفظ المالي الدائم.

الإصلاح:
- إضافة `mutateVolatile` للـ telemetry فقط (سجلات التكامل وآخر استخدام API key).
- منع telemetry من بدء كتابة PostgreSQL مستقلة على `app_state`.
- الإبقاء على `mutateDurable` وOptimistic Revision Guard للبيانات المالية والتشغيلية.
- عدم تغيير Parser جاد أو USD/EUR/ILS أو منطق الأرصدة.
- استبعاد `data/` من Docker build context.
- إضافة اختبار regression يمنع عودة تداخل telemetry مع حفظ جاد.
