# تقرير الإصدار 25.14.73 — الأمان وموثوقية الجلسات

## النتيجة

الإصدار يعالج الثغرات الحرجة التي كشفها فحص 25.14.72، ويضيف اختبارات سلوكية تمنع عودتها. لم تتغير معادلات الأعمال المالية أو مخطط PostgreSQL.

## الإصلاحات المنفذة

1. **Android WebView:** الثقة الآن في `https://alaboud-business-suite-us-763786484727.us-central1.run.app` فقط بمطابقة كاملة للمخطط والمضيف والمنفذ. أي صفحة أخرى تُفتح خارجيًا ويُفصل عنها جسر Android.
2. **تسجيل الدخول بالبصمة:** الرمز طويل الأمد لا يخرج إلى JavaScript. Android يرسل طلب المصادقة عبر HTTPS ويثبت كوكي الجلسة ثم يعيد حدث نجاح/فشل فقط.
3. **نطاق البيانات:** `users` و`branches` و`devices` و`sessions` أصبحت بيانات شركة، بينما تظل الحركات المالية بيانات فرع. هذا يصلح الإنشاء والإبطال والحفظ الفعلي.
4. **إبطال الاعتماد:** تسجيل الخروج يبطل الجلسة، وتغيير/إعادة تعيين كلمة المرور وتعطيل المستخدم يبطل الجلسات ورموز البصمة ذات الصلة.
5. **المدير الأول:** لا يسمح الإنتاج بكلمة المرور الموثقة الافتراضية، والحساب الجديد يجب أن يغير كلمة المرور قبل استخدام التطبيق.
6. **التسجيل العام:** مغلق افتراضيًا في الإنتاج، مع مسار حالة للواجهة ومتغير صريح لفتحه عند الحاجة.
7. **حماية موصلات الشركات:** حظر الشبكات الخاصة وعنوان metadata، إعادة فحص كل redirect، تثبيت اتصال HTTP على عنوان DNS الذي تم فحصه، وإبقاء تحقق TLS إلزاميًا في HTTP وPlaywright.
8. **التبعيات:** `nodemailer 9.0.5` و`vite 8.2.1` و`@vitejs/plugin-react 6.0.5`؛ نتيجة audit النهائية صفر.
9. **CI:** Node 22، ومسح رسمي لكل ملفات الاختبار الخلفية، واختبارات الواجهة وE2E وبناء الإنتاج وتدقيق التبعيات كلها بوابات فعلية.
10. **تنظيف:** حذف 44 نسخة ملاحظات إصدار متطابقة من الجذر و13 نسخة من `docs/`، و7 ملفات selftest و43 اختبار إصدار أرشيفي ميت، وإعدادات Render القديمة وworkflow Android مكرر وملفات مصدر جذرية ميتة. كما استُبدلت نسخ تشغيل Windows المكررة والمكسورة بملفين صحيحين في الجذر.

## ملاحظة Android

تمت إضافة اختبار مصدر يمنع عودة مطابقة `run.app` الجزئية أو حدث كشف الرمز. لم يتوفر `gradle-wrapper.jar` ولا Gradle محليًا في بيئة الفحص، لذلك بناء APK الفعلي متروك لـworkflow الرسمي `build-android-apk.yml` الذي يثبت Gradle 8.10.2 وJava 17.

## إعداد الإنتاج المطلوب

- `DATABASE_URL` لقاعدة PostgreSQL الدائمة.
- `JWT_SECRET` عشوائي قوي وفريد.
- `INITIAL_ADMIN_PASSWORD` قوي وليس القيمة الافتراضية الموثقة.
- إبقاء `PUBLIC_COMPANY_REGISTRATION_ENABLED=false` ما لم توجد حاجة تجارية واضحة للتسجيل الذاتي.
- تنفيذ `npm test` ثم نشر مراجعة `--no-traffic` بواسطة `DEPLOY_CLOUD_RUN_V25_14_73.ps1` واختبارها قبل تحويل الحركة.
