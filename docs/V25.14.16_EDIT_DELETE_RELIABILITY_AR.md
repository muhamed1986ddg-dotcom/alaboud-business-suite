# v25.14.16 — موثوقية التعديل والحذف

يعالج هذا الإصدار حالة نجاح الإضافة مع تعثر التعديل أو الحذف أثناء اضطراب PostgreSQL أو انقطاع تأكيد الاستجابة.

- يعاد إرسال طلب الكتابة مرة واحدة فقط بنفس `Idempotency-Key` بعد التحقق من عدم وجود إيصال COMMIT.
- إذا كانت العملية الأولى ما زالت قيد التنفيذ، لا تنشأ عملية ثانية؛ ينتظر العميل إيصال العملية الأصلية.
- إذا كانت العملية قد تم تثبيتها، يعرض الخادم النتيجة المحفوظة بدل إعادة التنفيذ.
- أزيل التحقق الثاني الزائد بعد حذف الحوالة؛ `mutateDurable()` لا يعود إلا بعد نجاح `COMMIT`، لذلك كان التحقق الإضافي قادرًا على إنتاج خطأ 500 كاذب.
- لم يتم تحويل العمليات المالية إلى write-behind، وتبقى الإضافة والتعديل والحذف Durable ومتوافقة مع آلية Commit Confirmation.
