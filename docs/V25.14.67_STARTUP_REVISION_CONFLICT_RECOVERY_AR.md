# v25.14.67 — استرداد تعارض المراجعة أثناء بدء التشغيل

## سبب الإصدار

أثناء الانتقال من مراجعة Cloud Run قديمة إلى مراجعة جديدة، نفذت المراجعة القديمة كتابة أخيرة بعد أن حمّلت المراجعة الجديدة حالة التطبيق. رفض PostgreSQL كتابة البدء القديمة بأمان بالخطأ `STALE_STATE_REVISION`، لكن مسار بدء الخدمة كان يصنف هذا التعارض كخطأ غير قابل للاسترداد، فبقيت المراجعة الجديدة على `503` رغم سلامة اتصال قاعدة البيانات.

## الإصلاح

- تصنيف `STALE_STATE_REVISION` ذي الحالة `409` والعلامة `retryable=true` كخطأ تشغيلي قابل للاسترداد.
- إعادة تحميل أحدث حالة مؤكدة من PostgreSQL قبل محاولة بدء التشغيل التالية.
- منع إعادة التحميل إذا كانت هناك كتابة معلقة، لحماية ترتيب الكتابات.
- مسح خطأ الحفظ السابق بعد نجاح إعادة التحميل.
- إضافة اختبار انحدار يحاكي كتابة مراجعة Cloud Run أحدث بين التحميل والحفظ، ويتأكد من تحميل الحالة الجديدة ثم استمرار إعادة المحاولة.

## حدود التغيير

لا يغيّر هذا الإصدار أي حسابات مالية أو مسارات API أو بنية بيانات. يقتصر على دورة بدء الخدمة وتصنيف الخطأ وإعادة تحميل الحالة المؤكدة.

## نتيجة التشغيل المتوقعة

عند حدوث التعارض أثناء نشر لاحق، تسجل الخدمة `Application startup deferred`، تنتظر فترة إعادة المحاولة المحدودة، تعيد تحميل أحدث مراجعة من PostgreSQL، ثم تصبح `serviceReady=true` بدل البقاء الدائم على `503`.
