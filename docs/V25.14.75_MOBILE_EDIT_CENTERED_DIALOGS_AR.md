# الإصدار v25.14.75 — إصلاح التعديل وتوسيط نوافذ الهاتف

## المشكلة

بعد اعتماد حاوية تمرير مستقلة لمحتوى التطبيق على الهاتف، بقيت عدة أزرار تعديل تستخدم `window.scrollTo`. كان النموذج يُنشأ فعلًا أعلى الصفحة، لكن موضع الشاشة لا يتحرك إليه، فيبدو للمستخدم أن زر التعديل لا يعمل. وفي صفحة الشركات الموحدة كان زر التعديل يملأ النموذج بينما قسم النموذج نفسه يبقى مخفيًا.

نوافذ تأكيد الحذف وتصفير حساب العميل كانت تظهر كلوحة سفلية، وقد تمتد أزرارها خلف شريط تنقل Android.

## الإصلاح

- إضافة مسار مشترك يكشف نموذج التعديل بعد أن ينتهي React من رسمه داخل `main.app-main-content`.
- ربطه بتعديل الحوالات ودفعات العملاء والعملاء والمصروفات وحركات ودفعات الشركات ومعلومات الشركة.
- فتح نموذج الشركة تلقائيًا عند اختيار التعديل من الصفحة الموحدة.
- توسيط `AppModal` على الهاتف مع حد ارتفاع ديناميكي ومسافات آمنة وأزرار ثابتة داخل النافذة.
- توحيد تأكيد حذف الدين وإغلاق الجرد مع نافذة التأكيد المشتركة.

## التحقق

- اختبار مسار الكشف عن المحرر داخل حاوية الهاتف والفallback الآمن.
- اختبار وجود ربط التعديل في جميع الأقسام المتأثرة.
- اختبار أن نافذة الهاتف في المنتصف وتراعي المساحة الآمنة.
- تشغيل اختبارات الواجهة وبناء Vite الإنتاجي.

لا يتضمن هذا الإصدار أي تغيير في المعادلات المالية أو قاعدة البيانات. Android shell يبقى على v25.14.74؛ يلزم نشر Web/Backend v25.14.75 إلى Cloud Run فقط.
