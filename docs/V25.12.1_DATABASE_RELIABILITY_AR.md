# تقرير إصدار v25.12.1 — موثوقية قاعدة البيانات

## سبب الإصدار
ظهرت على الهاتف إشعارات «قاعدة البيانات غير متصلة» و«جارٍ إعادة الاتصال»، مع فشل تأكيد حفظ الحوالة.

## الأخطاء التي تم إصلاحها
1. كان شريط حالة قاعدة البيانات يعتمد على `response.ok` العام لمسار الصحة. هذا الحقل قد يكون `false` بسبب فحص جاهزية آخر حتى عندما تكون PostgreSQL متصلة. أصبح الشريط يعتمد على `database.ok` مباشرة.
2. أصبح العميل يقرأ جسم استجابة `/api/health` حتى عندما يعيد الخادم HTTP 503، بدل تصنيف الحالة فورًا كاتصال مقطوع.
3. أصبح فحص إعادة الاتصال ديناميكيًا: يبدأ بعد 3 ثوانٍ عند ظهور مشكلة، ثم يتدرج حتى 15 ثانية، ويعود إلى 45 ثانية بعد نجاح الاتصال.
4. أضيف وقت آخر اتصال ناجح إلى التنبيه.
5. رُفعت محاولات الكتابة التفاعلية الافتراضية من 2 إلى 4، وميزانية الانتظار من 2.5 ثانية إلى 12 ثانية، مع بقاء العملية غير معتمدة إذا لم يصل تأكيد PostgreSQL.
6. رُفعت مهلة طلبات الكتابة في الواجهة إلى 35 ثانية حتى لا يقطع Axios الطلب بينما الخادم ما زال يعيد الاتصال.
7. تم توحيد أرقام الإصدار في الويب والخادم وAndroid إلى 25.12.1.

## الفحوصات المنفذة
- نجاح اختبارات الحساب الرقمي للدين لنا.
- نجاح فحص الاتساق المالي.
- نجاح فحص الملفات الحساسة.
- نجاح اختبار منطق شريط حالة قاعدة البيانات.
- نجاح فحص صياغة PostgresStateAdapter.

## قيود بيئة الفحص
لم يعمل اختبار PostgreSQL الذي يستورد حزمة `pg` لأن `node_modules` غير موجودة في بيئة العمل. يجب أن يشغله GitHub Actions بعد `npm ci`، ثم اختبار Render الفعلي قبل اعتماد الإنتاج النهائي.
