# v25.14.121 — إصلاحات الاعتماد النهائي

## الإصلاحات

- إصلاح أسعار الحوالات متعددة العملات عبر رسم تحويل موحد يسمح بالمسارات غير المباشرة مثل EUR → USD → CAD وSYP → USD → CAD.
- استخدام نفس آلية المسارات عند تحويل عملة سعر التكلفة/سعر العميل إلى القيمة المحاسبية CAD.
- إضافة `treasuryMovements` إلى النسخة الاحتياطية التشغيلية الشاملة والاستعادة، مع اختبار يمنع رجوع المشكلة.
- الحفاظ على السعر الأصلي وعملته عند تعديل حوالة دون تغيير السعر المحاسبي؛ وإذا غُيّر السعر من واجهة قديمة تعتمد CAD فقط، تُحدّث بيانات التدقيق إلى CAD بدل إبقاء اقتباس قديم غير صحيح.
- توسيع `run-backend-test-sweep.js` ليشغّل `.test.js` و`.test.mjs`.
- تحديث اختبارات WhatsApp والشركات القديمة لتستخدم العقود الحالية بدل التوقعات المتقادمة.
- Android: `versionName=25.14.121` و`versionCode=2514121`.
- تحويل GitHub Android workflow من Debug APK إلى Release APK موقّع والتحقق من التوقيع باستخدام `apksigner`.
- توحيد إعداد التسجيل العام على `PUBLIC_COMPANY_REGISTRATION=false`.
- Production Readiness يرفض `APP_URL` المفقود أو غير HTTPS في بيئة الإنتاج.

## أسرار توقيع Android المطلوبة في GitHub

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

لا تُحفظ أي مفاتيح أو كلمات مرور داخل المستودع.

## اختبارات الإصدار المنفذة

- `npm run check:current` — ناجح.
- `npm run check:reliability` — ناجح، مع تخطي اختبارات Runtime التي تحتاج اعتماديات غير موجودة محليًا في أرشيف المصدر.
- `npm run check:regressions` — ناجح.
- جميع اختبارات Backend من نوع `.test.mjs`: 24/24 ناجحة.
- فحص الملفات الحساسة: ناجح.
- Frontend: 36/38 اكتملت بنجاح في بيئة الفحص؛ الاختباران المتبقيان يتطلبان حزمة Vite غير الموجودة داخل نسخة `node_modules` الجزئية في الملف الأصلي. بعد `npm ci --prefix frontend` يجب تشغيل المجموعة كاملة في CI.

## قبل النشر

1. ضبط `APP_URL` على رابط HTTPS العام للخدمة.
2. تشغيل `npm run install:all` من بيئة لديها اتصال npm.
3. تشغيل `npm run check:release`.
4. عند بناء Android من GitHub، إضافة أسرار التوقيع الأربعة أعلاه.
