## 4. Voice Commands Phase 2 security review

The voice feature is intentionally limited in scope.

### Supported behavior

Voice commands are used for navigation and read-oriented operations, including opening application pages, locating customers, reading customer balances, opening the latest transfer view, showing overdue customers, and navigating to exchange-rate functionality.

### Financial mutation protection

Direct voice execution of financial or destructive operations is explicitly blocked. The reviewed implementation contains the safety rule:

> "الأوامر المالية لا تُنفذ صوتيًا في هذه المرحلة"

Transfers, payments, deletion, and modification are therefore not intended to execute directly from recognized speech.

### WhatsApp reminder behavior

The voice command for an account reminder prepares/opens the relevant customer workflow for manual review. It does not directly send the message from the voice component. The operator retains a manual confirmation step.

## 5. Android microphone permission review

The Android microphone permission path uses trusted-origin validation consistent with the application's JavaScript bridge protection.

The reviewed logic validates the trusted web permission origin using:

- HTTPS
- exact `APP_HOST` matching
- port 443

This limits microphone permission granting to the expected application origin and provides layered protection around the WebView/native boundary.

**Priority:** Recommended maintenance / regression-hardening improvement.  
**Security impact:** Preventive; reduces the chance of future voice-command regressions escaping the standard release gate.
