# v25.14.57 — Multi-Instance & Idempotency Safety

هذا الإصدار يبني فوق نقطة الاستقرار v25.14.56، ولا يغيّر أي معادلة مالية أو منطق أرصدة جاد.

## ما تم تغييره

- جعل إيصالات منع التكرار `operation_receipts` مقيدة بالشركة فعليًا عبر `scope_key` مع هوية مركبة: `(scope_key, operation_key, method, path)`.
- نقل إعادة تشغيل الإيصال الدائم إلى middleware يعمل بعد المصادقة، حتى لا يتم الاعتماد على `X-Company-ID` المرسل من العميل.
- إضافة migration آمنة لتعبئة `scope_key` للسجلات القديمة وإنشاء الفهرس المركب المطلوب.
- إضافة حماية optimistic revision على `app_state.revision`: أي snapshot قديم لا يستطيع الكتابة فوق commit أحدث؛ العملية تتوقف بـ HTTP 409 بدل lost update.
- جعل إنشاء جلسة الدخول وسجل تصدير النسخة الاحتياطية يمران عبر `mutateDurable` بدل الكتابة غير المؤكدة.
- توسيع CI ليشغّل اختبارات regression الرئيسية للحسابات، الجلسات، جاد، Rasel، الـPool، timeout وidempotency قبل البناء.

## ملاحظة تشغيلية

الإعداد الحالي الموصى به يبقى `minScale=1` و`maxScale=1`. حماية revision تجعل أي تشغيل متعدد النسخ يفشل بأمان عند stale snapshot بدل فقد البيانات، لكنها لا تحول المعمارية الحالية إلى multi-writer native SQL بالكامل.
